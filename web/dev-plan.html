Guppy Dev Plan

Dashboard

Concept

Guppy is a ROS 2-first ROV. The MCU owns low-level sensors and actuators. The onboard single-board computer runs ROS 2 and bridges commands, telemetry, video, and web ground-control access.

Design Philosophy

The project follows an innovation/design-thinking loop: collect data, make an MVP, test it, record feedback, and improve. Slow is smooth, smooth is fast.

Architecture

  • guppy_interface: ROS message definitions.
  • guppy: ROS 2 to MCU serial bridge.
  • guppy_web: Flask static host, dashboard, rosbridge launch, video launch.
  • Browser UI: Bootstrap dashboard using roslibjs.
  • rosbridge_suite: browser websocket access to ROS topics.
  • web_video_server: camera stream for the browser.

Message Meaning

  • GuppyDriverTransmitted: ground/web/control to ROS to MCU command path.
  • GuppyDriverReceived: MCU/ROS to ground/web telemetry path.

Current MVP

  • Keep legacy serial behavior working.
  • Add /guppy/cmd_vel and /guppy/cmd_raw command paths.
  • Add /guppy/telemetry alias.
  • Host a clean Bootstrap operator dashboard.
  • Use keyboard control first, with deadman safety.
  • Prepare browser-side controller support for later FlySky/gamepad work.

Future Ideas

  • Config page with localStorage.
  • Loadable controller mapping files.
  • FlySky i6S support through browser-side controller handling.
  • Richer telemetry history and test feedback capture.
  • Future non-ROS high-performance bypass, outside this ROS-only session.
